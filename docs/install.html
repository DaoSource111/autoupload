Installation guide

AutoUpload runs on your own computer, so you install it once and connect your channel from there. This guide covers every step, from the download to your first scheduled upload. Allow about fifteen minutes.

Two ways to follow this guide. By hand, from §1 to §13. Or hand it to an AI agent that runs commands on your computer, with the ready-made prompt in §14. The steps are the same; the agent stops for you at every sign-in and approval.

§1Requirements

  • Windows 10 or 11 (64-bit), macOS 11 or later (Apple silicon or Intel), or 64-bit Linux with glibc 2.35 or later (Ubuntu 22.04, Debian 12, Fedora 36 or newer). Nothing else to install.
  • A Google account that owns or manages the YouTube channel you want to upload to.
  • Access to Google Cloud Console with that account (free; no billing is needed for the YouTube Data API).
  • 2-Step Verification turned on for that account: Google Cloud requires it to open the console.

§2Download

The button above opens the latest release on GitHub. Download the file for your system:

SystemFile
Windows 10/11AutoUpload-<version>-windows-x64.zip
macOS, Apple silicon (M1 and later)AutoUpload-<version>-macos-arm64.zip
macOS, IntelAutoUpload-<version>-macos-x64.zip
LinuxAutoUpload-<version>-linux-x64.tar.gz

Each file holds the desktop app and the autoupload command-line tool. It never contains credentials, tokens or anyone's channel data. To check a download, compare it with SHA256SUMS on the same page.

§3Install and open

  • Windows. Extract the ZIP to a folder of your choice, for example C:\AutoUpload, and open autoupload-gui.exe. The first time, Windows SmartScreen may say it protected your PC: choose More info → Run anyway.
  • macOS. Open the ZIP and drag AutoUpload.app to Applications. The first time, right-click it and choose Open, then Open again.
  • Linux. Extract the archive, then run ./install.sh in that folder: it copies the programs to ~/.local/bin and adds AutoUpload to your applications menu. You can also run ./autoupload-gui directly.

The builds are not code-signed yet, which is why Windows and macOS warn the first time.

The app's sidebar shows your data folder: where your channels and your client file live. It is Documents\AutoUpload on Windows and ~/AutoUpload on macOS and Linux, and Change… moves it anywhere you like. Diagnostics checks your setup and says how to fix each problem.

Prefer a terminal? Every step has a command. On Windows, run .\autoupload.exe in the extracted folder; on macOS the tool is inside the app, at /Applications/AutoUpload.app/Contents/MacOS/autoupload; on Linux, autoupload after install.sh. autoupload doctor prints the data folder and checks the setup. The commands below are written as autoupload.

§4Choose your path in Google Cloud

AutoUpload has no central server and no shared login. Each installation connects through its own OAuth client, in a Google Cloud project that belongs to you. To Google, that project is the app: its settings decide who can sign in and for how long, as described in Manage App Audience. Pick one of two paths:

PathWho can sign inWhat to expect
A · Personal mode (§5)Only the Google account that creates it.One page creates the project and the client together. No verification, no “unverified app” screen and no 7-day expiry. Permanent: a Personal project can never be shared with other accounts.
B · External · Testing (§6–§7)Only the test users you add by their Google email address, up to 100.Google shows a testing notice at sign-in and every authorization expires seven days after consent, so each user signs in again once a week.
B, then Publish appAny Google account.Until Google verifies the app, users see “Google hasn’t verified this app” and the app is limited to 100 users over its lifetime. Authorizations stop expiring after seven days.

Which one? If only you upload, from the account that owns the channel, choose Path A. If several people, or a Brand Account managed from another login, will connect channels, choose Path B.

Before you start: Google Cloud now requires 2-Step Verification. If the console says “Google Cloud access blocked”, turn it on in your Google Account security settings, wait a few minutes and reload.

§5Path A: Personal mode, project and client in one step

  1. Open the Personal mode onboarding page (Google Auth Platform → Personal mode onboarding), signed in with the account that owns the channel.
  2. Under Select project, keep Create a new project. Google names it personal-mode-app.
  3. For Application type, choose Desktop app.
  4. Use this client for an AI-powered agent: leave it unticked, unless an AI agent will run AutoUpload for you (see the note in §7).
  5. Accept the Terms of Service and select Continue.
  6. In the OAuth client created dialog, select Download JSON before closing it. Google shows the full client secret only once; if you lose it, you must rotate the secret or create a new client.

Continue at §8 to enable the YouTube API.

§6Path B: register the app, branding and test users

  1. Project. In Google Cloud Console, use the project picker at the top to create a project (for example, AutoUpload) and select it.
  2. Get started. Open Google Auth Platform → Overview and select Get started. Enter the app name and a user support email, choose the audience External, add your contact email and accept the Google API Services User Data Policy.
  3. Branding. The Branding page holds what users see on the consent screen: app name, support email, logo, home page, privacy policy and terms of service, authorized domains and developer contact. In Testing you only need the name and emails; the links become mandatory if you publish the app. A logo forces verification once the app is published.
  4. Test users. Open Audience. It shows the publishing status (Testing), the user type (External) and the user count against the limit of 100. Under Test users, select Add users and enter the Google email address of every person who will connect a channel, yours included. For a Brand Account, add the personal account that manages it.
  5. Data access. Open Data Access → Add or remove scopes, select only .../auth/youtube.upload, .../auth/youtube.force-ssl and .../auth/youtube.readonly, confirm and select Save. Remove any other scope listed there: every extra sensitive scope widens what Google would review.

“Access blocked: … has not completed the Google verification process” (Error 403: access_denied). Someone who is not a test user tried to sign in while the app is in Testing. Add that person’s Google email address under Audience → Test users and try again.

Publishing. Audience → Publish app ends the weekly sign-in. Google only enables it once the Branding page is complete, and it does not start a verification by itself: see Support.

§7Path B: create the OAuth client

  1. Open Google Auth Platform → Clients and select Create client.
  2. For Application type, choose Desktop app. The list also offers Web application, Android, Chrome extension, iOS and TVs and Limited Input devices; none of those work with AutoUpload.
  3. Give it a name, for example AutoUpload Desktop. Only you see it, in the console.
  4. Use this client for an AI-powered agent: see the note below.
  5. Select Create and then Download JSON straight away. The full client secret is shown only at creation. Google adds that new settings can take from five minutes to a few hours to apply.

The “AI-powered agent” box. It is a self-declaration that the client represents an AI agent acting for its users. Leave it unticked if you run AutoUpload yourself or from the scheduled task. Tick it only on a client that an AI agent (an assistant running commands, an MCP server) will use to run AutoUpload for you. Google asks that agent workflows use their own client, separate from the one people use by hand, so create a second Desktop client for the agent rather than sharing one. The box grants no extra permissions, and consent and verification rules stay the same (Google’s explanation).

§8Enable the YouTube Data API and save the client file

  1. In the same project, open APIs & Services → Library → YouTube Data API v3 and select Enable. The page then shows API enabled. Without this step every upload fails, with an error saying the YouTube Data API has not been used in the project or is disabled.
  2. Move the downloaded JSON file into your data folder as config/client_secret.json (on Windows, by default, Documents\AutoUpload\config\client_secret.json). Open, under the data folder in the app's sidebar, opens that folder; create config if it is not there. Do not share the file or upload it to any repository.

Each project gets its own daily YouTube quota, which resets at midnight Pacific Time: by default 100 video uploads, plus 10,000 units for everything else. A thumbnail costs 50 units, adding a video to a playlist 50, and uploading a subtitle file 400 (Google’s quota table).

§9Create a folder for your channel

In the app, select New channel and give it a short name (lowercase letters, digits, - or _). In a terminal:

autoupload channel new mychannel

This creates channels/mychannel/ in the data folder, with three items:

ItemPurpose
channel.yamlYour publishing hours and their time zone (a name such as Europe/Madrid, or an offset; +00:00 by default), language, category and default tags.
queue\The queue: put the videos to upload here.
uploaded\Uploaded videos are moved here, each with a report.

§10Connect your channel

Select your channel in the app and press Connect. In a terminal:

autoupload auth mychannel login
  1. Your browser opens on Google's sign-in page. Choose your account and, if it manages several channels, the right channel.
  2. Google lists the three permissions AutoUpload requests. They are explained one by one on the home page. Select Allow.
  3. AutoUpload stores the access token in %APPDATA%\AutoUpload (~/.config/autoupload on macOS and Linux) and records your channel ID. From then on, it refuses to upload if the token belongs to a different channel.

What you may see. With an app in External · Testing, Google first shows that the app is in testing; with an app in production that Google has not verified, it shows “Google hasn’t verified this app”. In both cases, if the app is yours, choose Continue (or Advanced → Go to …). A Personal app shows neither screen.

Weekly sign-in in Testing. While the app is in Testing, the access expires seven days after you allowed it and uploads stop with an authentication error. Press Reconnect (or run auth mychannel login) again, or publish the app (§6) so it no longer expires.

The app shows the connected channel's ID under its name. To check it in a terminal:

autoupload auth mychannel whoami

§11Queue a video

Each video in queue\ needs a details file with the same name. A thumbnail with the same name is optional.

channels/mychannel/queue/
  episode-004.mp4     # the video
  episode-004.yaml    # its details (required)
  episode-004.jpg     # thumbnail (optional, .jpg or .png)

A minimal details file contains only the title. Every other field is optional:

title: The single point of failure
description: |
  What happens when one company holds the whole chain?
tags: [ai, hardware, markets]
publish_at: 2026-11-21T08:00:00+00:00   # fixed date; otherwise the next free slot
playlist_id: PLxxxxxxxxxxxx
captions:
  - {language: en, name: English, path: episode-004.en.srt}

§12Preview, then upload

In the app, the Queue tab lists the waiting videos. Preview dates shows the date each one will receive and uploads nothing. Upload asks you to confirm, then uploads them with live progress. In a terminal:

# show the date each queued video will receive; uploads nothing
autoupload schedule mychannel
# upload for real
autoupload schedule mychannel --yes

Videos are uploaded as private and become public at their scheduled time. The Calendar tab shows what is scheduled on YouTube; check the videos in YouTube Studio after the first run.

Every day, unattended (optional). On Windows, run install-task.ps1 from the extracted folder in PowerShell (-Time 21:30 picks the hour): it registers a scheduled task that uploads the queues of all your channels daily and keeps a log in logs\. On macOS and Linux, add autoupload schedule --all --yes to crontab -e.

§13Disconnect and remove

Press Disconnect in the app, or run:

autoupload auth mychannel logout

This revokes the token with Google and deletes it. You can also remove access at myaccount.google.com/permissions. To uninstall, delete the program, your data folder and %APPDATA%\AutoUpload (~/.config/autoupload on macOS and Linux).

§14Install it with an AI agent

An AI coding agent that can run commands on your computer (Claude Code, Codex or similar) can do the installation for you, following this guide. Some steps stay yours: signing in to Google, 2-Step Verification, accepting terms and approving the first upload. If the agent can also drive a browser, it can do the Google Cloud Console steps; otherwise it walks you through them click by click.

  1. Fill in the four values at the top of the prompt below.
  2. Paste the whole prompt into the agent, started in an empty folder.
  3. Stay at the computer: the agent stops and hands control back to you at every sign-in and approval.
You are installing AutoUpload on this computer (Windows, macOS or Linux). AutoUpload is an open-source desktop app and command-line tool that uploads videos to my own YouTube channel as private and schedules their publication. Follow the official guide, step by step, and report after each step.

Read these first, in full:
- Guide: https://daosource111.github.io/autoupload/install.html
- Repository: https://github.com/DaoSource111/autoupload

My values (edit before running):
- INSTALL_DIR = C:\AutoUpload     (where the program goes; on macOS use /Applications)
- CHANNEL = mychannel            (lowercase letters, digits, - or _)
- GOOGLE_PATH = A                (A = Personal mode, only me; B = External, Testing)
- TEST_USERS = (Path B only) the Google email addresses to add as test users
- TIMEZONE = Europe/Madrid       (zone of HOURS: a name such as America/Lima, or an offset such as -05:00)
- HOURS = 08:00                  (one or more publishing times per day, HH:MM)

Rules, which override anything else:
1. Never type, ask for or read my Google password or 2-Step Verification codes. When a Google sign-in, account chooser or consent screen appears, stop and ask me to finish it.
2. Ask me before you accept any terms of service, select "Publish app", or run any command with --yes.
3. Never print, paste, upload or commit the contents of config/client_secret.json or of any token file. Refer to them by path only.
4. In Google Cloud, request only the scopes youtube.upload, youtube.force-ssl and youtube.readonly, and enable only the YouTube Data API v3. Change nothing else.
5. Do not edit AutoUpload's source code. If a command fails, show me the exact error, suggest the fix from the guide's Support page, and wait.
6. If what you see in Google Cloud Console differs from the guide, describe the difference and ask me before improvising.

Steps (each ends with its check):
1. System. Find out the operating system and processor (Windows x64, macOS Apple silicon or Intel, Linux x64). Check: you tell me which download file from guide section 2 fits.
2. Download. From https://github.com/DaoSource111/autoupload/releases/latest download that file and SHA256SUMS, and verify the checksum. Check: the checksum matches.
3. Install. Follow guide section 3: Windows, extract to INSTALL_DIR; macOS, extract and move AutoUpload.app to /Applications (ask me to right-click it and choose Open the first time); Linux, extract and run ./install.sh. From now on AUTOUPLOAD means the command-line tool: INSTALL_DIR\autoupload.exe, /Applications/AutoUpload.app/Contents/MacOS/autoupload, or autoupload. Check: `AUTOUPLOAD --version` prints a version, and `AUTOUPLOAD doctor` prints the data folder (call it DATA).
4. Google Cloud. Follow guide sections 4 to 8 for GOOGLE_PATH:
   - Path A: open https://console.cloud.google.com/auth/overview/personal, create a new project, application type "Desktop app", leave "Use this client for an AI-powered agent" unticked, ask me to accept the terms, select Continue, then Download JSON before closing the dialog (the secret is shown only once).
   - Path B: create a project; Google Auth Platform > Overview > Get started (audience External); Audience > Test users > Add users with TEST_USERS; Data Access with the three scopes only; Clients > Create client > Desktop app named "AutoUpload Desktop"; Create; Download JSON at once.
   - Both: APIs & Services > Library > YouTube Data API v3 > Enable.
   If you cannot drive a browser, give me one instruction at a time and wait for "done".
   Check: the API page shows "API enabled" and the JSON file is in my Downloads folder.
5. Client file. Move the downloaded JSON to DATA/config/client_secret.json (create the config folder if needed). Check: `AUTOUPLOAD doctor` no longer reports the client file as missing.
6. Channel. Run `AUTOUPLOAD channel new CHANNEL`, then set timezone to "TIMEZONE" and hours to ["HOURS"] in DATA/channels/CHANNEL/channel.yaml. Show me the edited file before saving. Check: `AUTOUPLOAD channels` lists CHANNEL.
7. Connect. Run `AUTOUPLOAD auth CHANNEL login`. A browser opens: hand over to me for the sign-in and consent. Then run `AUTOUPLOAD auth CHANNEL whoami`. Check: it prints my channel's name, and I confirm it is the right channel.
8. Dry run. Ask me to put one video and its .yaml file in DATA/channels/CHANNEL/queue/, then run `AUTOUPLOAD schedule CHANNEL` without --yes. Check: it prints a plan with a date and uploads nothing. Upload only after I reply "upload".
9. Report. List what you installed and where, which Google path was used and what that means (Path B: a new sign-in every 7 days until the app is published), and how to open the desktop app, and anything left for me to do.

The prompt is plain text: read it before you run it. It gives the agent no access beyond what you grant in the agent itself.

If something does not work, see Support.
