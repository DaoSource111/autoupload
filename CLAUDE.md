# AutoUpload

YouTube upload automation for Windows, macOS and Linux (desktop app + CLI + MCP server for AI agents): each video in
`channels/<channel>/queue/`, with its YAML sheet, is uploaded as private and scheduled in the channel's next free
publishing slot (YouTube Data API v3). Fully local: no server; each user brings their own OAuth client and quota.
Author: Ellipsio Studio. Its main differentiators: 100% Rust native binaries, local-first, built for AI agents.

**Stack:** Rust ≥1.80 Cargo workspace · reqwest (blocking, rustls) · rusqlite (bundled) · chrono + chrono-tz ·
serde_yaml · clap · Slint 1.x (desktop app styled like the website, Barlow fonts embedded).
Public website: static HTML/CSS in `docs/` (GitHub Pages), generated by `tools/site` (Rust). No Python anywhere.
AI agent guide for users and contributors: `AGENTS.md`.

## Language — always English
- **English is the project's primary language. All documentation is written in English, always**: CLAUDE.md,
  AGENTS.md, `docs/*.md` (progress, decisions, known issues), README.md, CHANGELOG, CONTRIBUTING, SECURITY, code
  comments, doc comments, CLI messages, commit messages, PR descriptions and release notes.
- Spanish exists only as a translation of user-facing material (`README.es.md`, `docs/_src/es/`). English is the
  source of truth: write or change the English text first, then update the Spanish translation to match.
- This applies even when the conversation with the user is in Spanish.

## Run and test
On this machine Rust lives in `D:\DevTools` and **build output goes to `D:\DevTools\cargo-target`** (user env var
`CARGO_TARGET_DIR`; drive E: is nearly full, never build into `E:\autoupload\target`). In Bash first run
`export PATH="/d/DevTools/cargo/bin:$PATH" RUSTUP_HOME='D:\DevTools\rustup' CARGO_HOME='D:\DevTools\cargo' CARGO_TARGET_DIR='D:\DevTools\cargo-target'`.
```powershell
cargo test --workspace                                   # tests, no network (FakeApi / DemoApi)
cargo clippy --workspace --all-targets -- -D warnings ; cargo fmt --all
cargo run -p autoupload -- --demo channels               # any command on sample data, offline
cargo run -p autoupload -- doctor                        # offline setup check, shows the data folder
cargo run -p autoupload -- schedule <channel>            # plan only, uploads nothing
cargo run -p autoupload -- schedule <channel> --yes      # real upload (real channel!)
cargo run -p autoupload-gui -- --demo                    # desktop app on sample data
cargo run -p autoupload-gui                              # real data: set AUTOUPLOAD_HOME=E:\autoupload
cargo run -p autoupload-site                             # rebuild docs/ from docs/_src/
```

Never run `schedule --yes`, `task run`, `auth … login` or the app's Upload/Connect buttons against real data unless
the user asks: they act on real channels. Use `--demo` for screenshots and trials; screenshots must never show real
channels, accounts or local user paths.

Releases: bump `version` in the root `Cargo.toml` (`[workspace.package]`) and run `cargo build` so `Cargo.lock`
follows, date the section in `CHANGELOG.md`, push, then push a tag `vX.Y.Z`; `.github/workflows/release.yml` tests,
builds the Windows, Linux and macOS packages, attests them and publishes the GitHub release.

## Conventions
- Rust: `deny_unknown_fields` on config structs (unknown keys are errors); clippy clean with `-D warnings`; `cargo fmt`.
- Every remote call goes through the `Api` trait (`client::api_for`); tests use `FakeApi`/`DemoApi`, never the network.
- Every user-visible action (app, CLI, task, agent) is recorded with `activity::Actor::record`.
- Agents: reads, queueing, sheets and previews are free; uploads need `agents_may_upload`; never `allow_public`.
- 1.x compatibility: never change the token JSON, `channel.yaml` keys or the SQLite schema without a migration.
- Safe by default: nothing is uploaded without `--yes`, nothing goes public without `--allow-public`, and the token must belong to the expected channel.
- CLI exit codes: `OK=0, INVALID=2, AUTH=3, REMOTE=4`.
- Small, descriptive commits, with `Co-Authored-By` when Claude contributed.
