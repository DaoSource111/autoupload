Descargar AutoUpload (ZIP) Repositorio en GitHub

§1Requisitos

  • Windows 10 o Windows 11.
  • Python 3.10 o posterior, desde python.org. Durante la instalación, marca Add python.exe to PATH.
  • Una cuenta de Google que sea propietaria o administradora del canal de YouTube al que quieres subir.
  • Acceso a Google Cloud Console con esa cuenta (gratuito; la YouTube Data API no requiere facturación).

§2Descarga

Descarga el ZIP de arriba y descomprímelo en la carpeta que prefieras, por ejemplo C:\AutoUpload. Si usas Git, también puedes clonar el repositorio:

git clone {REPO}.git C:\AutoUpload

El repositorio contiene solo el código fuente. Nunca contiene credenciales, tokens ni datos de ningún canal.

§3Instalación

Abre PowerShell en esa carpeta (en el Explorador, clic derecho → Abrir en Terminal) y ejecuta:

# crea un entorno de Python propio para AutoUpload
py -m venv .venv
# instala AutoUpload y sus dependencias en él
.\.venv\Scripts\pip install .
# comprueba que el comando funciona
.\.venv\Scripts\subidor.exe --help

La herramienta de línea de comandos se llama subidor. Sus órdenes están en inglés; los nombres originales en español siguen funcionando como alias.

§4Crea un proyecto en Google Cloud y habilita la API

AutoUpload se conecta a YouTube mediante un cliente OAuth que es tuyo. El archivo del cliente, client_secret.json, nunca se publica ni se comparte. Cada instalación crea el suyo:

  1. Entra en Google Cloud Console con la cuenta de Google propietaria o administradora de tu canal y crea un proyecto (por ejemplo, AutoUpload).
  2. Abre APIs y servicios → Biblioteca, busca YouTube Data API v3, ábrela y pulsa Habilitar. Sin este paso todas las subidas fallan, con un error que dice que la YouTube Data API no se ha usado en el proyecto o está inhabilitada.

§5Elige quién puede usar la app

Abre Google Auth Platform → Público (la primera vez, Google te pide configurar la app con Comenzar). El tipo de usuario y el estado de publicación deciden quién puede iniciar sesión y cuánto dura el acceso, según la guía de Google Administra el público de la app:

ConfiguraciónQuién puede iniciar sesiónQué esperar
PersonalSolo la cuenta de Google que creó el proyecto.Sin verificación, sin la pantalla de «app no verificada» y sin caducidad a los 7 días. Es una elección única al crear el proyecto: no se puede cambiar después ni compartir con otras cuentas.
Externo · PruebaSolo los usuarios de prueba que añadas por su correo de Google, hasta 100.Google muestra una advertencia antes de dar acceso y cada autorización caduca siete días después del consentimiento: cada usuario debe volver a iniciar sesión una vez por semana.
Externo · En producciónCualquier cuenta de Google.Mientras Google no verifique la app, los usuarios ven la pantalla de «app no verificada» y la app tiene un límite de 100 usuarios en total. Las autorizaciones dejan de caducar a los siete días.

Recomendado para una persona: elige Personal si solo vas a subir tú, desde la misma cuenta propietaria del canal. Para un equipo pequeño: empieza en Externo · Prueba, añade a cada persona como usuario de prueba y pulsa Publicar app cuando todo funcione, para dejar de iniciar sesión cada semana.

§6Marca, permisos y usuarios de prueba

  1. Marca. En Google Auth Platform → Desarrollo de la marca, escribe el nombre de la app y un correo de asistencia. Añade página principal, política de privacidad y condiciones del servicio si vas a publicar la app: Google las exige a las apps externas en producción. Deja el logotipo vacío salvo que vayas a pedir la verificación, porque el logotipo la exige.
  2. Acceso a los datos. En Acceso a los datos → Agregar o quitar permisos, añade solo youtube.upload, youtube.force-ssl y youtube.readonly. No añadas otros: cada permiso sensible extra amplía lo que Google revisa.
  3. Usuarios de prueba (solo Externo · Prueba). En Público → Usuarios de prueba, pulsa Agregar usuarios y escribe el correo de Google de cada persona que vaya a conectar un canal. Si el canal es una cuenta de marca, añade la cuenta personal de Google que la administra.

«Acceso bloqueado: … no completó el proceso de verificación de Google» (Error 403: access_denied). Aparece cuando alguien que no es usuario de prueba intenta iniciar sesión mientras la app está en Prueba. Añade el correo de Google de esa persona en Público → Usuarios de prueba y vuelve a intentarlo.

§7Crea el cliente OAuth

  1. En Google Auth Platform → Clientes, pulsa Crear cliente y elige el tipo de aplicación App de escritorio.
  2. Créalo y descarga el archivo JSON.
  3. Guárdalo en la carpeta de AutoUpload como config\client_secret.json. No lo compartas ni lo subas a ningún repositorio.

§8Crea una carpeta para tu canal

.\.venv\Scripts\subidor.exe channel new micanal

Esto crea canales\micanal\ con tres elementos:

ElementoPara qué sirve
canal.yamlTus horas de publicación, zona horaria, idioma, categoría y etiquetas por defecto.
queue\La cola: aquí pones los videos por subir.
uploaded\Aquí se mueven los videos ya subidos, cada uno con su informe.

§9Conecta tu canal

.\.venv\Scripts\subidor.exe auth micanal login
  1. Se abre tu navegador en la página de inicio de sesión de Google. Elige tu cuenta y, si administra varios canales, el canal correcto.
  2. Google enumera los tres permisos que pide AutoUpload. Se explican uno a uno en la página de inicio. Pulsa Permitir.
  3. AutoUpload guarda el token de acceso en %APPDATA%\subidor-youtube y anota el ID de tu canal. Desde entonces se niega a subir si el token pertenece a otro canal.

Qué puedes ver. Con la app en Externo · Prueba, Google avisa primero de que la app está en pruebas; con la app en producción y sin verificar, muestra «Google no verificó esta app». En ambos casos, si la app es tuya, elige Continuar (o Configuración avanzada → Ir a …). Una app Personal no muestra ninguna de las dos pantallas.

Inicio de sesión semanal en Prueba. Mientras la app está en Prueba, el acceso caduca siete días después de permitirlo y las subidas se detienen con un error de autenticación. Vuelve a ejecutar auth micanal login, o publica la app (§5) para que deje de caducar.

Para comprobar qué canal está conectado:

.\.venv\Scripts\subidor.exe auth micanal whoami

§10Pon un video en la cola

Cada video de queue\ necesita una ficha con el mismo nombre. La miniatura con el mismo nombre es opcional.

canales\micanal\queue\
  episodio-004.mp4     # el video
  episodio-004.yaml    # su ficha (obligatoria)
  episodio-004.jpg     # miniatura (opcional, .jpg o .png)

La ficha mínima solo lleva el título. Todo lo demás es opcional:

titulo: The single point of failure
descripcion: |
  ¿Qué pasa cuando una sola empresa controla toda la cadena?
etiquetas: [ia, hardware, mercados]
fecha: 2026-11-21T08:00:00-05:00   # fecha fija; si no, el siguiente horario libre
lista: PLxxxxxxxxxxxx
subtitulos:
  - {language: es, name: Español, path: episodio-004.es.srt}

§11Revisa el plan y sube

# muestra la fecha que recibirá cada video de la cola; no sube nada
.\.venv\Scripts\subidor.exe schedule micanal
# sube de verdad
.\.venv\Scripts\subidor.exe schedule micanal --yes

Los videos se suben en privado y se hacen públicos a su hora programada. Revísalos en YouTube Studio después de la primera vez.

§12Desconectar y desinstalar

.\.venv\Scripts\subidor.exe auth micanal logout

Esto revoca el token ante Google y lo borra. También puedes quitar el acceso en myaccount.google.com/permissions. Para desinstalar, borra la carpeta de AutoUpload y %APPDATA%\subidor-youtube.

Si algo no funciona, consulta Soporte.
